# lhg-mp-profile：目标人群画像

> 目标：动手编食谱前，先把"给谁吃"问清楚。人群错了，食谱越精致越危险。
> 核心纪律：**慢病/备孕人群先出免责声明；过敏原问两遍；不给治疗性承诺。**

> **免责声明**：本 skill 输出仅供一般性膳食参考，非医疗建议。慢病/备孕人群请遵医嘱。

## 1. 何时使用

- 用户说"帮我出一周食谱" → 先走本 skill，不许直接编菜
- 用户只说了"我要减脂" → 用第 3 节把画像补全
- 拿到一份别人的食谱想改 → 先确认原人群与现人群是否一致

## 2. 输入输出

**输入**：用户口述的目标与身体情况。

**输出**：人群画像卡（`profile.md`），包含：人群类型、目标、过敏原/忌口、做饭条件、预算、不适用声明。

## 3. 分步方法论

### 3.1 人群四选一

| 人群 | 核心诉求 | 本插件能做的 | 本插件不做的 |
|---|---|---|---|
| 减脂 | 热量缺口、可持续 | 定缺口区间、保证蛋白质 | 不承诺"一周瘦 X 斤" |
| 增肌 | 热量盈余、蛋白质充足 | 定盈余区间、练后餐建议 | 不开补剂方案 |
| 备孕 | 营养均衡、避开禁忌 | 均衡食谱、禁忌清单 | 不做"助孕食谱"承诺 |
| 慢病 | 配合治疗、避开禁忌 | 一般性低盐/控糖食谱 | 不替代医嘱、不承诺疗效 |

人群只能四选一。不属于这四类（如运动员备赛、术后恢复）→ 明确告知超出范围，建议咨询专业人士。

### 3.2 四维采集清单

1. **目标**：具体、可衡量（"3 个月减 5kg"可以，"变瘦"不行）
2. **过敏原与忌口**：问两遍。第一遍开放式问（"有什么过敏或不吃的东西？"），第二遍按清单核对（花生/坚果/海鲜/蛋/奶/麸质/大豆/芝麻）
3. **做饭条件**：自己做 / 外卖为主 / 食堂 / 不会做饭——条件决定食谱的"做法复杂度"上限
4. **预算范围**：每餐预算大概多少——决定蛋白质来源（鸡胸肉 vs 牛排）

### 3.3 慢病/备孕专项

- 输出画像卡之前，先展示免责声明并请用户确认"已知晓"
- 慢病追问具体类型：高血压（控盐）、糖尿病（控糖）、高血脂（控油）——不同类型禁忌不同
- 备孕确认：是否已在医生指导下备孕？如用户提到正在服药 → 只给一般性建议，提醒遵医嘱
- **红线**：不许说"这个食谱能帮你降血压/降血糖"。能说的是"这是一份低盐食谱，可作为日常饮食参考，具体请遵医嘱"

### 3.4 画像卡模板

```markdown
## 人群画像卡
- 人群：减脂
- 目标：3 个月减 5kg（每周约 0.4kg）
- 过敏原：花生（已二次确认）
- 忌口：不吃香菜
- 做饭条件：自己做，会基础烹饪
- 预算：每餐 20~30 元
- 不适用声明：本画像不构成医疗建议；慢病/备孕相关事项请遵医嘱
- 状态：已确认 / 待补充
```

### 3.5 特殊饮食需求

| 需求 | 处理方式 |
|---|---|
| 素食（蛋奶素） | 蛋白质来源切到蛋/奶/豆制品，全周≥3 种仍然适用 |
| 纯素 | 明确告知：纯素+减脂的蛋白质达标难度大，建议咨询营养师；本插件可编但会标注"蛋白质缺口风险" |
| 清真 | 肉类来源限定牛羊肉/鸡肉，画像卡备注 |
| 乳糖不耐 | 牛奶→舒化奶/豆浆，画像卡记为"类过敏原"同等对待 |

### 3.6 采集话术库（直接可用）

- 开场："我们先定个小目标——你希望 3 个月后有什么不一样？"
- 挖过敏原（第一遍）："有没有吃完不舒服、起疹子、拉肚子的食物？"
- 挖过敏原（第二遍）："我按清单跟你核对一遍：花生、坚果、海鲜、鸡蛋、牛奶、面筋、大豆、芝麻，有没有中招的？"
- 挖做饭条件："平时做饭吗？如果 10 分是'大厨'，你给自己打几分？"
- 挖预算："一顿饭大概愿意花多少钱？20 块以内，还是 30~50？"
- 收尾："还有没有什么我没问到、但你觉得我应该知道的？"（好信息常藏在这里）

### 3.7 常见画像组合示例

```markdown
## 画像卡示例 A：减脂上班族
- 人群：减脂 / 目标：3 个月减 5kg
- 过敏原：无（已二次确认）/ 忌口：香菜
- 做饭条件：工作日晚餐自己做，午餐食堂
- 预算：每餐 15~25 元
- 备注：午餐需配食堂替换方案

## 画像卡示例 B：备孕女性
- 人群：备孕 / 目标：营养均衡
- 过敏原：海鲜（已二次确认）/ 忌口：无
- 做饭条件：自己做，会基础烹饪
- 预算：每餐 30~50 元
- 备注：已在医生指导下备孕；不设热量缺口
```

## 4. 反模式

- ❌ 用户说"我要减脂"就直接编 7 天食谱——没问过敏原，等于埋雷
- ❌ 对慢病用户承诺"按这个吃，血糖能下来"——这是医疗承诺，越界
- ❌ 只问一遍过敏原——很多人第一次会漏说，清单核对是第二遍的意义
- ❌ 画像卡未经用户确认就进入测算——人群错了，后面全错
- ❌ 把"不吃香菜"和"花生过敏"同等对待——过敏是 blocker，偏好是 warning，分级不同

## 5. 自检与反馈

每次执行完本 skill，做一次轻量自检：

1. 四维是否都问到了？→ 缺一维就补。
2. 过敏原是否问了两遍？→ 只问一遍不算数。
3. 慢病/备孕用户是否看到了免责声明？→ 没看到不许往下走。

标准冒烟用例：用 `fixtures/good/meta.json` 的人群信息反推画像卡，检查四维是否齐全（见 `smoke_test.py`）。

反馈渠道：以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-meal-plan/issues，正文写清"输入 → 错误输出 → 期望输出"。

## 6. 人群画像的边界案例

以下情况本插件明确不接，请直接转交专业人士：

| 情况 | 为什么不接 | 转交谁 |
|---|---|---|
| 肾病/透析患者的饮食 | 蛋白质与钾磷限制高度个体化，算错有危险 | 主治医生 + 临床营养师 |
| 术后恢复期饮食 | 与手术类型强相关 | 主治医生 |
| 儿童/青少年减脂 | 影响生长发育，目标设定完全不同 | 儿科医生 |
| 运动员备赛期 | 周期化营养，超出四类人群 | 运动营养师 |
| 进食障碍史 | 热量计算本身可能触发问题 | 心理医生 + 营养师 |

遇到以上情况，标准话术："你的情况比较特殊，为了安全起见，我建议你咨询 XX。这份画像卡我可以帮你整理成文档，方便你带去问诊。"

### 6.1 画像卡的复用与更新

- 画像卡有效期：体重变化超过 3kg、目标变化、新增过敏原 → 画像卡过期，重走本 skill
- 画像卡存档：建议存为 `profile-YYYYMMDD.md`，每次调食谱时先核对画像卡是否过期
- 多人共用：给家人也编食谱时，一人一张画像卡，不许共用（过敏原和目标都不同）
